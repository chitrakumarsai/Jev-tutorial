# ADR 0004: A scenario registry, with per-scenario scoring summarised for the UI

- **Status:** Accepted (2026-10-10)
- **Context:** Milestone 1 built only S1, so the run service, API routes, CLI, scorer and results UI all imported S1 directly. Milestone 2 adds S2 (clause review) and S3 (citation check), whose findings, answer keys and scorecards don't involve money. Copying the S1 wiring per scenario would duplicate the budget, replay and event code that must behave identically across scenarios.
- **Decision:** Each scenario is a frozen `ScenarioSpec` in `jev.scenarios.registry` (id, title, description, the exact LLM instructions and schema, document and answer-key loaders, a factory for its Jev and LLM pipelines, and a data validator). `RunService` runs any spec; the app holds one service per registered scenario, and the API and CLI look scenarios up by id (unknown → 404 `UNKNOWN_SCENARIO`; the CLI also accepts each spec's explicit short `alias`, such as `s1`). Pipelines satisfy two protocols in `jev.scenarios.base`, `JevSidePipeline` and `LlmSidePipeline`, so budget pre-flight, replay, recording and events stay in one place. Scoring becomes per scenario too (task R2): each scorer returns a generic scorecard with item statuses plus API-supplied `summary` rows, so the UI renders any scenario's results without per-scenario result components.
- **Consequences:** Adding a scenario means adding data, two pipelines, a scorer and one spec. Every scenario's service is built at startup, so missing or invalid data for any scenario stops the app (fail fast, on purpose for a rehearsed demo; `data validate` names the scenario). Spec ids and aliases must match the replay id pattern because the id is also the recordings folder name. Pipelines receive `Settings`, not just the review threshold. Pre-flight reserves for every request a pipeline *could* make (for S3, also citations that code will reject as fabricated without calling Jev), which over-estimates on purpose. CLI output now names scenarios by id (`OK: s1_reconciliation …`) instead of "S1". S1 behaviour is unchanged (golden replays and E2E pass as before). Recordings stay per scenario id under `data/replays/<id>/`.
